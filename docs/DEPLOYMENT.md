# Deployment preparation

Public source: https://github.com/SamirGedeon/ledgerly

The repository contains a local-development Compose stack. It is not a hosted application. Serve the compiled frontend from an HTTPS reverse proxy with SPA fallback, route /api to Rails, and use managed PostgreSQL for a production deployment.

Required API runtime settings: RAILS_ENV=production, SECRET_KEY_BASE, DATABASE_URL, APP_HOST, FRONTEND_ORIGIN. SECRET_KEY_BASE can be generated by `bundle exec rails secret`. Keep FORCE_SSL=true behind correctly configured TLS termination. Supply secrets through protected platform settings, never source files.

Build frontend with `npm ci && npm run build`. Serve frontend/dist with fallback to index.html for /overview, /transactions, /budgets and /categories. Do not expose Vite as the public production server. Run `bundle exec rails db:migrate` as a release step.

Provision the first owner using protected WORKSPACE_NAME, OWNER_NAME, OWNER_EMAIL and OWNER_PASSWORD environment values, then run `bundle exec rails workspace:bootstrap`. Demo seeds cannot run in production. Viewer provisioning currently requires a trusted administrator; there is no invitation/self-signup flow.

Before real use: configure database backups and test restore, monitor errors, centralize login rate limiting if scaling, expire old session rows, and define customer-data retention. Imports are synchronous and bounded; no queue/Redis is configured.

Dockerfiles accept an optional BuildKit proxy_ca secret for enterprise/cloud CA bundles. For example: `docker build --secret id=proxy_ca,src=/path/to/trusted-ca.pem -t ledgerly-api ./backend`. TLS verification remains enabled. npm uses NODE_EXTRA_CA_CERTS; Ruby uses SSL_CERT_FILE on that build step. Enterprise apt certificate provisioning belongs in a trusted base-image workflow.

The delivered Dockerfiles/full Compose startup were not built end-to-end in the constrained development executor. API/PostgreSQL containers and the host Vite process were exercised separately; see VERIFICATION.md. No paid hosting resources were created.
